## Введение в СиАОД

### Конструкции ветвления

#### Базовая конструкция IF
```
IF (условие)
  <действие>
FI
```

#### Ветвление с альтернативными условиями
```
IF (условие1)
  <действие1>
ELSE IF (условие2)
  <действие2>
FI
```

#### Полное ветвление IF-ELSE
```
IF (условие)
  <действие1>
ELSE
  <действие2>
FI
```

**Пояснение:**
- `FI` завершает конструкцию ветвления (обратное от IF)
- Отступы показывают вложенность блоков
- Условия записываются в круглых скобках

### Конструкции повтора (циклы)

#### Цикл с предусловием (while-loop)
```
DO (условие)
  <действия>
OD
```

**Особенность:** Условие проверяется **ПЕРЕД** выполнением тела цикла

#### Цикл с постусловием (do-while loop)
```
DO
  <действия>
OD (условие)
```

**Особенность:** Условие проверяется **ПОСЛЕ** выполнения тела цикла (гарантирует минимум одно выполнение)

#### Цикл с параметром (for-loop)
```
DO (i := 1, 2, ..., n)
  <действия>
OD
```

**Особенность:** Переменная i последовательно принимает значения от 1 до n

#### Бесконечный цикл с условием выхода
```
DO
  <действия>
  ...
  IF (условие) OD FI
  ...
OD
```

**Особенность:** Цикл выполняется бесконечно, пока не встретится конструкция выхода

### Дополнительные замечания

#### Синтаксические особенности:
- Ключевые слова обычно пишутся **заглавными буквами**
- `OD` завершает конструкцию цикла (обратное от DO)
- Условия всегда в круглых скобках
- Тело конструкций выделяется отступами

#### Практические примеры:
**Пример с ветвлением:**
```
IF (temperature > 30)
  PRINT "Жарко"
ELSE IF (temperature > 20)
  PRINT "Тепло"
ELSE
  PRINT "Прохладно"
FI
```

**Пример с циклом:**
```
DO (i := 1, 2, ..., 5)
  PRINT "Итерация: ", i
OD
```

## Сортировка: основные понятия и определения

### Зачем изучать сортировки?
**Причины обращения к задаче сортировки в курсе:**
1. **Сортировка – фундаментальная деятельность**, без которой не обходится ни одна обработка реальных данных, цель которой - облегчить (ускорить) последующий поиск элементов в отсортированном массиве.
2. **На примере сортировки удобно рассматривать множество алгоритмов**, сравнивать и анализировать их

### Математическое определение сортировки
Пусть дан массив $$A = { a_1, a_2, ..., a_n }$$
Для всех его элементов определены **операции отношения**: меньше, больше, равно (\( <, >, = \))
Необходимо **отсортировать массив**, т.е.
переставить элементы массива \( A \) таким образом, что выполняется одно из следующих неравенств:
$$a_1 \leq a_2 \leq a_3 \leq ... \leq a_n \quad (1)$$
$$a_1 \geq a_2 \geq a_3 \geq ... \geq a_n \quad (2)$$

### Типы упорядочивания
- Если выполняется неравенство **(1)**, то массив отсортирован **по возрастанию** или в **прямом порядке**
- Если выполняется неравенство **(2)**, то массив отсортирован **по убыванию** или в **обратном порядке**

### Практическая значимость
Сортировка является одной из наиболее распространенных операций в программировании благодаря тому, что:
- **Упорядоченные данные обрабатываются эффективнее**
- **Ускоряется поиск** (бинарный поиск работает только на отсортированных массивах)
- **Упрощается анализ** и визуализация данных
- **Оптимизируются многие алгоритмы**, использующие предварительно отсортированные данные

### Пример применения
Исходный массив: [5, 2, 8, 1, 9]  
Отсортированный по возрастанию: [1, 2, 5, 8, 9]  
Отсортированный по убыванию: [9, 8, 5, 2, 1]  

Проверку правильности сортировки осуществляют с помощью:  
- Подсчет контрольной суммы - суммы всех элементов массива $$CS = \left(\sum_{i=1}^{n} data_i\right)$$  
- Подсчет количества серий - неубывающая последовательность максимальной длины  
  [5 6 8] [1 3 5 5] [4] [2 7] [6] - 5 неубывающих последовательностей = 5 серий  

Вычисляются до и после сортировки  
- Массив, отсортированный по возрастанию, состоит из одной серии.  
- В массиве, отсортированном по убыванию, количество серий равно количеству элементов в массиве (если все элементы различны)

### Сортировка элементов со сложной структурой
Ключ сортировки - та часть информации, которая учитывается при определении отношения порядка.  
Пример: Телефонный справочник  
- Фамилия  
- Имя  
- Телефон  
- Адрес  

Пример ключа: фамилия и имя (составной ключ из двух полей)  
- Фамилия - старшая часть ключа  
- Имя - младшая часть ключа  

Ключ поиска обычно:  
- равен ключу сортировки, или  
- состоит из его старшей части  

Сортировка рассматривается с точки зрения двух свойств:  
1. **Устойчивость сортировки** (Сортировка называется устойчивой, если после её проведения в массиве не меняется относительный порядок элементов с одинаковыми ключами)  
   Пример:  
   ```
   Исходный: 1 2 5' 6 3 4 5"
   ```  
   Устойчивая сортировка:  
   ```
   1 2 3 4 5' 5" 6
   ```  
   Неустойчивая сортировка:  
   ```
   1 2 3 4 5" 5' 6
   ```  
   Вывод: Устойчивая сортировка лучше, чем неустойчивая, особенно когда данные уже были ранее упорядочены по другим ключам  
2. **Зависимость от исходной упорядоченности массива** (Эта характеристика показывает, изменяется ли трудоемкость сортировки в зависимости от исходных данных.)

### Трудоемкость сортировки
Операции, влияющие на трудоемкость:  
- Сравнение элементов - C ("Compare")  
- Перестановки элементов - M ("Move")  

Трудоемкость: $C + M = T$  
$C$ и $M$ зависят от количества элементов в массиве:
$C(n)+M(n)=T(n)$

Правила подсчета:
- Предварительно обнулить счетчики: C=0; M=0;
- При подсчете количества сравнений счетчик ставить перед условным оператором
- При подсчете количества пересылок счетчик ставить до или после оператора присваивания

Пример:  
```
C++;
if (a_i < x) ...
a_i = x; M++;
```

### Примечания по реализации
Алгоритмы написаны на естественном языке, где массив нумеруется от 1 до n: $A = {a_1, a_2, ..., a_n}$  
Для реализации на C++ массив можно описывать:  
```
int A[1+n];
```  
Элемент A[0] не используется:  
```
A[0] A[1] A[2] ... A[n]
```

## Метод прямого выбора SelectSort

### Описание метода
Метод прямого выбора (SelectSort) работает следующим образом:  
Находим наименьший элемент массива и переставляем его на первое место.  
Среди оставшихся элементов (начиная со второго) находим наименьший элемент и переставляем его на второе место в массиве.  
Среди оставшихся элементов (начиная с третьего) находим наименьший элемент и переставляем его на третье место  
и т. д.

### Алгоритм на псевдокоде
```
DO ( i := 1, 2, ... n-1)
	k := i
	DO  ( j := i+1, i+2,… ,n )
               IF ( aj < ak )  k := j   FI     
        OD
        ai <--> ak 
OD
```

### Пример сортировки
Исходный массив: К У Р А П О В А  
После шагов:  
А У Р К П О В А  
А А Р К П О В У  
А А В К П О Р У  
А А В К П О Р У  
А А В К О П Р У  
А А В К О П Р У  
А А В К О П Р У

### Трудоемкость
По количеству пересылок: на каждой итерации старшего цикла выполняется один обмен (3 пересылки).  
M = 3(n-1)  

По количеству сравнений:  
Когда i=1 требуется (n-1) сравнение,  
когда i=2 требуется (n-2) сравнения, и т.д.
С = (n-1) + (n-2) + (n-3) + … + 1 = n(n-1)/2  

Трудоемкость: T = C + M = O(n²), n→∞  

Значения M и C не зависят от исходной упорядоченности массива.  
Сортировка не устойчива.  
Пример: 3’ 3” 2 -> 2 3” 3’

### Классы сложности
T = O(n²)  

### Свойства
| Метод | Трудоемкость | Устойчивость | Зависимость от упорядочивания |
|-------|------------|------------|-----------------------------|
| SelectSort | $O(n^2)$ | не устойчив | не зависит |
| BubbleSort | - | - | - |
| ShakerSort | - | - | - |
| InsertSort | - | - | - |

## Пузырьковая сортировка BubbleSort

### Описание метода
Пузырьковая сортировка (BubbleSort) работает следующим образом:  
Двигаясь от конца массива к его началу, будем сравнивать между собой соседние элементы. Если правый элемент будет меньше, чем левый, то поменяем их местами.  
При первом проходе наименьший элемент переместится на первое место. При втором проходе наименьший элемент из оставшихся “всплывёт” на второе место, и т.д.  
Через (n-1) итерацию массив будет отсортирован.

### Алгоритм на псевдокоде
Обозначим i – номер итерации, j – индекс правого элемента в текущей паре.  
```
DO (i := 1, 2, ... n-1)
       DO (j := n, n-1, ... i+1)
              IF (aj < aj-1)  aj↔aj-1  FI
       OD
OD
```

### Пример сортировки
Исходный массив: К У Р А П О В А
После шагов:  
А К У Р А П О В  
А А К У Р В П О  
А А В К У Р О П  
А А В К О У Р П  
А А В К О П У Р  
А А В К О П Р У  
А А В К О П Р У

### Трудоемкость
По количеству сравнений: C = n(n-1)/2 (идентично SelectSort).  

Количество пересылок M зависит от исходной упорядоченности массива:  
1) Массив упорядочен -> M_min = 0  
2) Массив обратно упорядочен -> M_max = 3C  
3) Массив случайный -> M_ср = 3C/2  

Метод зависит от исходной упорядоченности по количеству пересылок.  
Пузырьковая сортировка устойчива.  

Трудоемкость: T = O(n²)

### Свойства
| Метод | Трудоемкость | Устойчивость | Зависимость от упорядочивания |
|-------|------------|------------|-----------------------------|
| SelectSort | $O(n^2)$ | не устойчив | не зависит |
| BubbleSort | $O(n^2)$ | устойчив | зависит |
| ShakerSort |-|-|-|
| InsertSort |-|-|-|

## Шейкерная сортировка ShakerSort

### Описание метода
Шейкерная сортировка (ShakerSort) является улучшением пузырьковой сортировки. В BubbleSort «легкие» элементы «всплывают» быстро, а «тяжелые» «тонут» медленно.  
Для уменьшения трудоемкости предложены два изменения:  
1) Изменение направления просмотра массива на каждой итерации.  
2) Установление границ рабочей части массива на место последнего обмена на каждой итерации.

### Алгоритм на псевдокоде
L, R – левая и правая границы рабочей части массива, n – количество элементов в массиве.  
```
L := 1, R := n, k := n,
DO
	DO ( j := R, R-1, ... L+1)
		IF (aj < aj-1)  aj↔aj-1,  k := j  FI
	OD
	L := k
	DO ( j := L, L+1, ... R-1)
		IF (aj > aj+1)  aj↔aj+1,  k := j  FI
	OD
	R := k
OD (L < R)
```

### Пример сортировки
Исходный массив: К У Р А П О В А  
После шагов:  
А К У Р А П О В  
А К Р А П О В У  
А А К Р В П О У  
А А К В П О Р У  
А А В К О П Р У  
А А В К О П Р У  
А А В К О П Р У

### Трудоемкость
Два усовершенствования в алгоритме позволяют уменьшить только количество сравнений.  
T = O(n²), n→∞  

Метод шейкерной сортировки сильно зависит от исходной упорядоченности массива по количеству сравнений.  
Метод обеспечивает устойчивую сортировку.

### Свойства
| Метод | Трудоемкость | Устойчивость | Зависимость от упорядоченности |
|-------|--------------|--------------|--------------------------------|
| SelectSort | $O(n^2)$ | не устойчив | не зависит |
| BubbleSort | $O(n^2)$ | устойчив | зависит |
| ShakerSort | $O(n^2)$ | устойчив | зависит |
| InsertSort | - | - | - |

## Метод прямого включения InsertSort

### Описание метода
Метод прямого включения (InsertSort) работает следующим образом:  
Начиная с i = 2 берём очередной i-й элемент массива и включаем его на нужное место среди первых (i-1) элементов, при этом все элементы, которые больше ai, сдвигаются на одну позицию вправо.

### Алгоритм на псевдокоде
```
DO ( i := 2, 3, …, n )
	t := ai,  j := i -1
	DO ( j > 0  и  t < aj )
		aj+1 := aj
		j := j -1
	OD
	aj+1 := t
OD
```

### Пример сортировки
Исходный массив: К У Р А П О В А  
После шагов:  
К У Р А П О В А  
К Р У А П О В А  
А К Р У П О В А  
А К П Р У О В А  
А К О П Р У В А  
А В К О П Р У А  
А А В К О П Р У

### Трудоемкость
Для определения трудоемкости оценим количество операций для каждого значения i:  
Cmin = 1, Cmax = i -1  
Мmin = 2, Мmax = i +1  

Тогда для всех i:  
Cmin = n -1, Cmax = n(n-1)/2  
Мmin = 2(n-1), Мmax = n(n-1)/2 + 2n - 2  

Средняя трудоемкость этого метода имеет квадратичный порядок T = O(n²), n→∞.  
Метод прямого включения устойчивый.  
Метод сильно зависит от исходной упорядоченности массива.

|-------|--------------|--------------|--------------------------------|
| SelectSort | $O(n^2)$ | не устойчив | не зависит |
| BubbleSort | $O(n^2)$ | устойчив | зависит |
| ShakerSort | $O(n^2)$ | устойчив | зависит |
| InsertSort | $O(n^2)$ | устойчив | сильно зависит |

## Метод Шелла ShellSort

### Описание метода
Метод Шелла (ShellSort) основан на оценках метода прямого включения InsertSort: чем лучше упорядочен массив, тем меньше операций потребуется для его сортировки.  
Основная идея состоит в предварительном улучшении порядка элементов массива, а затем окончательной сортировке его методом прямого включения.  
Предлагается работать в методе прямого включения с шагом k большим, чем 1, что предварительно улучшит упорядоченность массива.  
Чем больше величина шага, тем меньше операций сравнения и пересылки приходится выполнять.  

Предварительная сортировка массива методом прямого включения с шагом к > 1 называется к-сортировкой.  
Метод заключается в проведении сначала нескольких к-сортировок, а затем окончательной сортировки массива с шагом к=1.  
Обозначим H = (h1, h2, …, hm) – последовательность из m возрастающих шагов, где h1 = 1, h1 < h2 < h3 < … < hm.  
Производя последовательно к-сортировки с шагами hm, hm-1, .., h1, получим упорядоченный массив. Это гарантируется тем, что последний шаг h1 = 1.

### Алгоритм на псевдокоде
```
<вычисление массива шагов h>
DO ( k := hm, hm-1, … 1 )
	DO ( i := k+1, k+2, … n )
		t := ai,  j := i - k
		DO ( j > 0  и  t < aj )
			aj+k := aj
			j := j - k
		OD
		aj+k := t
	OD
OD
```

### Пример сортировки
Исходный массив: К У Р А П О В А  
После шагов (для большего шага):  
К У Р А П О В А  
К А Р У П О В А  
К А П У Р О В А  
К А П О Р У В А  
В А К О П У Р А  
В А К А П О Р У  

Затем (для меньшего шага):  
А В К А П О Р У  
А В К А П О Р У  
А А В К П О Р У  
А А В К П О Р У  
А А В К О П Р У  
А А В К О П Р У

### Трудоемкость
Эффективность метода по времени работы зависит от выбора значений шагов.  
Существует и часто используется следующая последовательность шагов:  
h1 = 1, hi = 2 hi-1 +1, i = 2,…m, m = -1.  
Пример для n = 100: m = 5, h1 = 1, h2 = 3, h3 = 7, h4 = 15, h5 = 31.  

При использовании этой последовательности шагов метод имеет порядок трудоемкости O(n^{1.2}), n→∞.  
Метод существенно быстрее методов с квадратичной трудоемкостью.  
В примере: Insert – 46 операций, Shell – 34 операции.  
Метод Шелла не устойчив.  
Метод зависит от исходной упорядоченности массива.

### Свойства
| Метод | Трудоемкость | Устойчивость | Зависимость от упорядоченности |
|-------|--------------|--------------|--------------------------------|
| SelectSort | $O(n^2)$ | не устойчив | не зависит |
| BubbleSort | $O(n^2)$ | устойчив | зависит |
| ShakerSort | $O(n^2)$ | устойчив | зависит |
| InsertSort | $O(n^2)$ | устойчив | сильно зависит |
| ShellSort | $O(n^{1.2})$ | не устойчив | зависит |

## Двоичный поиск BinarySearch

### Описание метода
Двоичный поиск (BinarySearch) применяется в упорядоченном по возрастанию массиве $A = (a_1, a_2, …, a_n)$, где $a_1 ≤ a_2 ≤ … ≤ a_n$.  
Цель: найти элемент с ключом X или все элементы с ключом X.  
Если массив не упорядочен, то используется перебор с трудоемкостью $O(n)$.  
Идея: взять средний элемент m и сравнить с X. Если $a_m = X$, элемент найден. Если $a_m$ < X, поиск в правой половине; если $a_m > X$, в левой.  
Вторая версия алгоритма уменьшает количество сравнений, исключая проверку на равенство в цикле, и находит самый левый элемент среди одинаковых ключей.

### Алгоритм на псевдокоде
(первая версия)
Обозначим 
  L,R - правая и левая границы рбочей части массива,
  
  **Найден** - логическая переменная в которой будем отмечать факт успешного завершения поиска.

```
L: = 1,  R: = n,  Найден: = нет
  DO ( L ≤ R ) 
    m: =  ⌊(L+R)/2⌋		
    IF (am=X)  Найден: =да  OD  FI
    IF (am < X)   L: = m+1
    ELSE  R: = m-1 
    FI
  OD
```

Массив: а б б б в г д е ж з и к (позиции 1-12), X = б  
(подчёркнута группа одинаковых элементов б б б в)

Шаги (фрагмент):  
L=1, R=12 → m=⌊(1+12)/2⌋=6 (элемент под номером 6 — г),  
г > б → продолжаем поиск в левой половине → 
R := m-1 = 5
→ рабочая часть сузилась до позиций
1-5: а б б б в
L=1, R=5

При дальнейших итерациях первая версия найдёт какой-то из элементов «б» (не обязательно самый левый) и завершит поиск.

Недостатки первой версии алгоритма:
1) на каждой итерации цикла два сравнения (сначала проверка am = X, затем выбор половины),
2) находит первый попавшийся элемент из нескольких с заданным

Рассмотрим вторую версию алгоритма, в которой уменьшим количество сравнений путем исключения из алгоритма проверки на равенство.
### Алгоритм на псевдокоде
(вторая версия)

```
L := 1, R := n  
DO (L < R)  
	m := ⌊(L + R)/2⌋  
	IF (am < X) L := m + 1  
	ELSE R := m  
	FI  
OD  
IF (a_R = X) Найден := да  
ELSE Найден := нет  
FI
```

### Пример
Массив: а б б б в г д е ж з и к (позиции 1-12), X = б  
Шаги:  
L=1, R=12 → m=6 (г), г > б → R=6  
L=1, R=6 → m=3 (б), б = б (но в цикле: б ≤ б, R=3)  
L=1, R=3 → m=2 (б), б ≤ б, R=2  
L=1, R=2 → m=1 (а), а < б, L=2  
L=2, R=2 → выход, a2=б, найден (самый левый).

Преимущества второй версии алгоритма:
1) на каждой итерации цикла одно сравнение,
2) находит самый левый элемент среди тех, которые  удовлетворяют ключу.

### Трудоемкость
Максимальное количество итераций k в худшем случае: k < log2(n) + 1.  
Трудоемкость: T = O(log n).  
Графики показывают логарифмический рост.

## Сортировка данных со сложной структурой ArrayStruct

### Описание метода
Для сортировки массива структур (например, абонентов с именем и телефоном) нужно определить отношение порядка (> < =) с помощью булевой функции less(X, Y), возвращающей 1 если X < Y, иначе 0.  
Функция less может зависеть от ключа (имя или телефон) или сложного ключа (имя, затем телефон).  
В алгоритмах сортировки заменить сравнение на вызов less, перестановки остаются.  
Преимущества: гибкое определение порядка, легкое изменение направления (знак в less), не требует переопределения пересылок (побайтовое копирование).  
Аналогично для поиска в таких структурах.

### Алгоритм на псевдокоде
(пример на пузырьковой сортировке)

```
DO (i = 1, 2, …, n-1)  
	DO (j = n, n-1, …, i+1)  
		IF (less(Aj, Aj-1)) Aj ↔ Aj-1 FI  
	OD  
OD
```

Функция less (пример по имени):

```
int less(struct abonent X, struct abonent Y) {  
	if (X.name < Y.name) return 1;  
	else return 0;  
}
```

По сложному ключу:
```
int less(struct abonent X, struct abonent Y) {  
	if (X.name < Y.name) return 1;  
	else if (X.name > Y.name) return 0;  
	else if (X.phone < Y.phone) return 1;  
	else return 0;  
}
```

### Пример
Массив A: Иванов (223322), Петров (345767), Абрамов (667891).  
Сортировка по имени: Абрамов, Иванов, Петров.  
По телефону: Иванов, Петров, Абрамов.  
По сложному ключу: если имена равны, то по телефону.

### Трудоемкость
Зависит от базового алгоритма сортировки (O(n²) для пузырьковой).  
Функция less добавляет постоянный overhead, но не меняет асимптотику.

## Индексация массивов IndexArray

### Описание метода
Индексация позволяет упорядочивать данные без физической перестановки элементов, используя индексный массив B с номерами элементов A.  
Доступ: A[B[i]].  
Для нескольких ключей строятся разные индексы (по возрастанию, убыванию).  
Построение: инициализировать B = (1,2,...,n), сортировать B, сравнивая A[B[j]] < A[B[j-1]], переставляя только в B.  
Преимущества: несколько индексов, нет копирования больших данных, фильтрация (только элементы по условию, e.g., четные).  
Используется для быстрого поиска (двоичный через индекс) и вывода.

### Алгоритм на псевдокоде
Построение индекса (на пузырьковой):

```
B := (1, 2, …, n)  
DO (i = 1, 2, …, n-1)  
	DO (j = n, n-1, …, i+1)  
		IF (a[bj] < a[bj-1]) bj ↔ bj-1 FI  
	OD  
OD
```

Вывод по возрастанию:

```
DO (i = 1, …, n)  
	вывод (A[B[i]])  
OD  
```

Двоичный поиск через индекс:

```
L := 1, R := n  
DO (L < R)  
	m := ⌊(L + R)/2⌋  
	IF (A[B[m]] < X) L := m + 1  
	ELSE R := m  
	FI  
OD  
IF (A[B[R]] = X) Найден := да  
ELSE Найден := нет  
FI
```

### Пример
Массив A: 5 7 3 4 2 6 1 8 (позиции 1-8).  
Индекс B (по возрастанию): 7 5 3 4 2 6 1 8 → A через B: 1 2 3 4 5 6 7 8.  
Индекс C (по убыванию): 8 2 6 1 4 3 5 7 → A через C: 8 7 6 5 4 3 2 1.  
Фильтрация (четные по возрастанию): D для 4,2,6,8 → A через D: 2 4 6 8.

### Трудоемкость
Построение индекса: как у базовой сортировки (O(n²) для пузырьковой).  
Доступ через индекс: O(1) дополнительно.  
Поиск: O(log n) через индекс.

## Пирамидальная сортировка HeapSort

### Описание метода
Пирамидальная сортировка (HeapSort) основана на структуре данных «пирамида» (куча, heap).  

**Определение пирамиды**  
Последовательность a_L , a_{L+1} , … , a_R называется **пирамидой**, если для всех i, у которых существует хотя бы один из потомков, выполняется  
ai ≤ min(a_{2i}, a_{2i+1}).

**Важные свойства пирамиды**
1. При двустороннем усечении (удалении первого и последнего элементов) оставшаяся часть остаётся пирамидой.  
2. В пирамиде a1 — минимальный элемент.  
3. Правая половина массива a_{⌊n/2⌋} , … , a_n всегда является пирамидой (у этих элементов нет потомков).

Сортировка происходит в два этапа:  
1. Построение начальной пирамиды из всего массива.  
2. Многократное извлечение минимального элемента (a1) в конец массива с последующим восстановлением свойства пирамиды на оставшейся части.

### Алгоритм на псевдокоде

#### Процедура построения пирамиды (просеивание вниз) Построение пирамиды (L, R)
(a_{L+1} , … , a_R — уже пирамида, добавляем/восстанавливаем элемент a_L)

```
x := aL, i := L
DO
	j := 2i
	IF (j > R) OD FI
	IF (j < R и aj+1 ≤ aj) j := j+1 FI
	IF (x ≤ aj) OD FI
	ai := aj
	i := j
OD
ai := x
```

#### Основной алгоритм HeapSort
```
L := ⌊n/2⌋
DO (L > 0)
	Построение пирамиды (L, n)
	L := L-1
OD

R := n
DO (R > 1)
	a1 ↔ aR
	R := R-1
	Построение пирамиды (1, R)
OD
```

### Пример сортировки
Исходный массив: К У Р А П О В А  

**Этап построения пирамиды** (снизу вверх, начиная с ⌊8/2⌋=4):  
После всех просеиваний получаем пирамиду:  
А В У П О Р К А  

**Этап извлечения минимума** (показаны состояния пирамиды после обмена a1↔aR и просеивания):  
А В У П О Р К А → А К В П О Р У А → А А В К П О Р У  
(далее процесс продолжается до полной сортировки)

Полная отсортированная последовательность:  
А А В К О П Р У

### Трудоемкость
Трудоемкость процедуры построения одной пирамиды (просеивания):  
C ≤ 2⌊log₂(R-L+1)⌋  M ≤ ⌊log₂(R-L+1)⌋ + 2

На первом этапе (построение начальной пирамиды) процедура вызывается n/2 раз.  
На втором этапе — (n−1) раз.  

Общая трудоемкость пирамидальной сортировки:  
**T = O(n log₂ n)**, n→∞  

Точные верхние оценки:  
C < 2n log₂ n + n + 2  
M < n log₂ n + 6.5n − 4  

Пирамидальная сортировка **не устойчива**.  
Метод **практически не зависит** от исходной упорядоченности массива.

### Свойства
| Метод       | Трудоемкость     | Устойчивость | Зависимость от упорядоченности |
|-------------|------------------|--------------|--------------------------------|
| SelectSort  | O(n²)            | не устойчив  | не зависит                     |
| BubbleSort  | O(n²)            | устойчив     | зависит                        |
| ShakerSort  | O(n²)            | устойчив     | зависит                        |
| InsertSort  | O(n²)            | устойчив     | сильно зависит                 |
| ShellSort   | O(n^{1.2})       | не устойчив  | зависит                        |
| HeapSort    | O(n log₂ n)      | не устойчив  | практически не зависит         |


# Быстрая сортировка (QuickSort)

## Теорема о сложности сортировки

**Для пересылок:** Если определена требуемая перестановка и имеется память для второй копии массива, то достаточно сделать $n$ пересылок.

**Важное замечание:** На сегодняшний день алгоритм, имеющий $n \log_2 n$ сравнений и $n$ пересылок, **неизвестен**.

## Быстрая сортировка (QuickSort) - метод Хоара (1962)

### Описание алгоритма

Самый быстрый из известных методов сортировки, использующий стратегию "разделяй и властвуй":

1. Берем произвольный элемент массива $X$
2. Просматриваем массив **слева**, находим элемент $a_i \geq X$
3. Просматриваем массив **справа**, находим элемент $a_j \leq X$
4. Меняем местами $a_i$ и $a_j$
5. Продолжаем процесс, пока $i \leq j$

В результате массив разделяется на две части:
- **Левая**: элементы $\leq X$
- **Правая**: элементы $\geq X$

Затем алгоритм рекурсивно применяется к каждой части.

### Визуализация разделения
```
a_i ≥ X        i     j        a_j ≤ X
≤ X                 ≥ X
```

### Алгоритм на псевдокоде
```pseudocode
QuickSort(L, R)
    х := а[L]
    i := L
    j := R
    DO (i ≤ j)
        DO (a[i] < x) i := i+1 OD
        DO (a[j] > x) j := j-1 OD
        IF (i <= j) 
            a[i] ↔ a[j]
            i := i+1
            j := j-1
        FI
    OD
    IF (L < j) QuickSort(L, j) FI
    IF (i < R) QuickSort(i, R) FI
```

### Пример сортировки
**Исходный массив:** К У Р А П О В А Е

**Процесс сортировки:**
```
К У Р А П О В А Е
Е У Р А П О В А К
Е А Р А П О В У К
Е А В А П О Р У К
                
Е А В А  
                
А    
А   В   Е 
               
А А В      
	       
А А В                    
   
А В                          
                                       
                                     
П О Р У К
                                     
К О Р У П
                                     
К О Р У П
                                                
П У Р
                                             
У Р
      
                                       
Р У
```

**Результат:** А А В Е К О П Р У

### Выбор опорного элемента

**Медиана:** Элемент $a_m$ называется медианой для элементов $a_L, ..., a_R$, если количество элементов меньших $a_m$ равно количеству элементов больших $a_m$ (с точностью до одного элемента).

**Пример:** В слове "КУРАПОВАЕ" буква К - медиана.

**Преимущество медианы:** массив разделяется на две равные части.

### Трудоемкость QuickSort

**Количество сравнений:** $C = n \log n$

**Количество пересылок:** $M = n \log n$ (не более одного обмена - 3 пересылки - на два сравнения)

**Средняя трудоемкость:** $O(n \log n)$, $n \rightarrow \infty$

**Пример для $n = 15$:**
- Делится на 7 и 7
- Затем на 3, 3, 3, 3
- Всего 3 итерации

## Проблема глубины рекурсии

### Определение рекурсии
Процедуры и функции, организующие вызовы "самих себя", называются **рекурсивными**

**Вычисление 4!:**
```
fact(4) = (((1×1)×2)×3)×4
fact(3) = ((1×1)×2)×3
fact(2) = (1×1)×2
fact(1) = 1×1
fact(0) = 1
```

### Проблема переполнения стека
- При каждом вызове создается новый **фрейм** в памяти
- $n$ вложенных вызовов → $n$ фреймов
- Существует опасность переполнения стека

### Оптимизация для QuickSort
**Стратегия:** вместо двух рекурсивных вызовов использовать один рекурсивный вызов, а другой заменить итерацией цикла.

**Вопрос:** Для какой части массива делать рекурсивный вызов?

**Ответ:** Для **меньшей по размеру** части массива.

```
-------------!--------------------------------!
L           j i                              R
```

| ShellSort | $O(n^{1.2})$ | не устойчив | зависит |
| HeapSort | $O(n \log_2 n)$ | не устойчив | практически не зависит |
| **QuickSort** | **$O(n \log n)$** | **не устойчив** | **зависит** |

# Динамические структуры данных: списки

## Адреса и указатели

### Основные понятия
- **Переменная** - объект программы с именем и значением
- **Имя переменной** соответствует **адресу** участка памяти
- **Значение переменной** - содержимое этого участка

```
Программный уровень: Переменная | Значение | Имя
Машинный уровень:    Участок памяти | Содержимое | Адрес
```

### Указатели
**Определение:** Указатель - переменная, значением которой является адрес объекта конкретного типа.

**Нулевой адрес:** обозначается константой `NULL`

**Графическое представление:**
```
p → x : tData
```

## Динамическая память

### Типы памяти
- **Статическая память** - выделяется при компиляции, освобождается при завершении программы
- **Динамическая память** - выделяется и освобождается по запросам программы

## Индексация через массив указателей

### Алгоритм построения
1. В массив `b` записываются адреса элементов массива `a`: `b = (&a₁, &a₂, &a₃, ..., &aₙ)`
2. Сортировка любым методом:
   - **Сравнение:** `a[bᵢ] < a[bᵢ₋₁]` или `*bᵢ < *bᵢ₋₁`
   - **Перестановки:** только в массиве `b`: `bᵢ ↔ bᵢ₋₁`

**Достоинство:** исходные данные могут располагаться произвольно в динамической памяти

## Линейные списки

### Определение
**Список** - последовательность однотипных элементов, связанных между собой указателями.

### Структура элемента списка
```c
struct tLE {
    tLE *next;
    int data;
} *head;
```

**Графическое представление:**
```
head → [data|next] → [data|next] → ... → [data|next] → NULL
```

**Оптимизация:** если поле `next` является первым элементом структуры, его адрес совпадает с адресом элемента списка

## Стек (LIFO)

**Дисциплина:** Last Input, First Output

### Основные операции со стеком

#### 1. Добавление элемента в начало
```pseudocode
p->data := <данные>
p->next := head
head := p
```

**Графически:**
```
head → [1] → [2] → NULL
         ↑
         p

После:
head → [p] → [1] → [2] → NULL
```

#### 2. Исключение первого элемента
```pseudocode
IF (head ≠ NULL)
    p := head
    head := p->next
    delete p
FI
```

#### 3. Просмотр списка
```pseudocode
p := head
DO (p ≠ NULL)
    операция(*p)
    p := p->next
OD
```

## Очередь (FIFO)

**Дисциплина:** First Input, First Output

### Основные операции с очередью

#### 1. Добавление элемента в конец

**а) В непустую очередь:**
```pseudocode
p->next := NULL
tail->next := p
tail := p
```

**б) В пустую очередь:**
```pseudocode
p->next := NULL
head := p
tail := p
```

**в) Универсальный алгоритм:**
```pseudocode
p→Next := NULL
IF (Head ≠ NULL)
    Tail→Next := p
ELSE 
    Head := p
FI
Tail := p
```

#### 2. Структура заголовка очереди
```c
struct Queue {
    tLE *head;
    tLE *tail;
} Q;
```

## Оптимизация операций с очередью

### Инициализация пустой очереди:
```pseudocode
tail := (tLE*) &head
```

**Графически:**
```
head → NULL
tail ↗
```

### Оптимизированное добавление:
```pseudocode
tail->next := p
tail := p
```

**Преимущество:** работает в два раза быстрее!

## Задача сортировки последовательностей

### Особенности последовательного доступа
- (k+1)-й элемент получается путем просмотра предыдущих k элементов
- Просмотр возможен только в одном направлении (слева направо)
- Методы сортировки для массивов не годятся для списков

### Операция добавления из стека в очередь
```pseudocode
Q.Tail→Next := List
Q.Tail := List
List := List→Next
```

## Ключевые термины на английском

- **list** - список (простой)
- **queue** - очередь  
- **next** - следующий
- **head** - голова
- **tail** - хвост

## Практические рекомендации

1. Для оптимизации размещайте поле `next` первым в структуре элемента
2. Используйте универсальные алгоритмы для работы с пустыми и непустыми очередями
3. Применяйте оптимизированную инициализацию очереди для повышения производительности
4. Для сортировки последовательностей разрабатывайте специализированные алгоритмы, учитывающие ограничения последовательного доступа
